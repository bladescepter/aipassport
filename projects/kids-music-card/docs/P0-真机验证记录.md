# P0 真机验证记录

本文记录 P0 联网固件在真实设备上的第一阶段验证：完整备份、最小刷写和应用分区启动确认。**尚未进行在线播放验收**，P0 未完成。

## 1. 设备与备份前状态

- 芯片：ESP32-C3 rev v1.1，8 MB 内置 Flash（XMC），USB Serial/JTAG 控制台 `/dev/ttyACM0`。
- 备份前运行固件：2026-09-22 构建，应用版本 `1`，属于 P0 代码之前的离线实现。
- 备份前 NVS 内容：`music:mode = 1`、`music:volume = 8`，**没有 `music_net` 命名空间**。
- 设备分区表与仓库 `partitions.csv` 完全一致，无需调整。

## 2. 完整 Flash 备份

备份在仓库外保存（本机 `~/Backups/kids-music-card-device/2026-10-02/`），不进入 Git：

- 应用分区（0x10000–0x24FFFF，2.25 MiB）：完整回读后逐字节一致
- musicfs 头部（0x250000–0x25FFFF）：逐字节一致
- 备份 NVS 通过 CRC 校验，可正常解析

## 3. 最小刷写范围

用「新 P0 构建」与设备现有内容逐区域比对，只刷写差异部分：

| 区域 | 比对结果 | 处理 |
| --- | --- | --- |
| bootloader (0x0) | 仅 42 字节不同，全部位于构建时间戳描述与尾部 SHA-256 | 不刷写 |
| 分区表 (0x8000) | 逐字节一致 | 不刷写 |
| 应用 (0x10000) | 旧版本，需要更新 | **刷写** |
| musicfs (0x250000) | 逐字节一致（6 首歌曲） | 不刷写 |

因此使用 `idf.py -B build/validation-63642d1/p0 -p /dev/ttyACM0 app-flash` 只写入应用分区，1,630,816 字节通过哈希校验，未重写 5.69 MiB 音乐分区。启动日志中 bootloader 仍显示原编译时间（2026-09-22），与未刷写 bootloader 的预期一致。

刷写后应用分区内容即 `build/validation-63642d1/p0/FoloToy-AI-Passport.bin`，可随时用备份恢复原固件。

## 4. 启动日志结论

串口日志保存在 `build/validation-63642d1/device/boot-console.log`。注意：应用启动时 USB CDC 会重新枚举，单次 `cat` 会漏掉启动输出，需用 ESP-IDF monitor 抓取。

确认结果：

- 应用版本 `63642d1`，编译时间与本次构建一致；启动完成，无崩溃、无重启循环、无看门狗复位。
- 分区表识别正确，`musicfs` 正常挂载为 `/music`。
- 外设初始化正常：ES8311 音频、CW2017 电量计、I2C、显示与 LVGL、ADC 三键。
- NVS 设置保留：`儿童音乐播放器就绪: 6 首, 音量 8/10, 模式 随机播放`。
- 无联网配置时按设计降级：`W main: Network profile/start unavailable: ESP_ERR_NVS_NOT_FOUND`，应用继续运行；该路径在任何 Wi-Fi 初始化之前返回，因此不会申请网络资源。
- 未出现 `HTTP source service unavailable` 警告，说明联网源服务初始化成功。
- `app_main` 正常返回，菜单与按键可用。

代码路径核对：无 profile 时选择 `HTTPS (P0)` 会走 `player_open` 失败分支，界面显示 `Error` 并返回，不会崩溃或阻塞。该行为仍待人工在设备上确认。

## 5. 尚未验证

本阶段**没有**触碰、也没有证明以下内容：

- 视觉与音频人工验收：菜单项与中文字形、6 首本地歌曲播放、长短按隔离、音量、三种播放模式、5 秒息屏与黑屏期间连续播放。
- 在线播放：TLS 握手、证书校验、Basic Auth、起播时延、Range 断点恢复、`200` 无 Range 时的受控重启。
- 弱网与异常：断网恢复、`401/403/404/5xx`、超时、缓冲欠载、暂停/停止/切歌期间的资源回收。
- 资源观测：TLS 最低堆、最大连续块、音频任务栈水位、任务退役后是否持续占用内存（本次仅见初始化时的堆布局）。
- 长时间稳定性：30 分钟连续播放。

## 6. 进入在线测试还缺什么

1. **私有 profile 注入方式**。代码目前只有 NVS 读取接口，没有写入入口。首选由主机侧用 ESP-IDF 官方 `nvs_partition_gen.py` 生成 NVS 镜像后只刷写 0x9000 分区，这样不需要新增固件代码，也便于用备份恢复。无论用哪种方式，都必须保留 `music` 命名空间的音量与模式，凭据不得进入仓库、日志或固件源码。
2. **一首歌的 HTTPS 端点和凭据**。服务端必须具备：有效证书、Basic Auth、精确 `Content-Length`、正确的 Range/`206` 与 `Content-Range`；不可重定向，不使用 chunked 或内容压缩。设备侧 `size_bytes` 必须等于裸 Opus 文件的精确字节数（可从本地 `assets/music/data/*.opus` 选用并上传）。
3. **验收参数**：先在 16 KiB 缓冲、4100 字节起播阈值下测，再比较 32 KiB。

以上 1、2 两项完成后，只需更新 24 KiB 的 NVS 分区即可开始在线测试，不需要重新刷写应用或音乐分区。
