# 曲库加载连接复用（已完成一轮真机回归）

工作目录：`projects/kids-music-card/`。

## 改动

- 曲库 worker 在一次请求内复用 HTTP client，顺序读取 current、manifest、page，目标是仅建立一次 TLS 连接；不并发打开多个 TLS 会话。
- 只有完整读取并验证 HTTP 响应、JSON 解析成功才保留连接给下一份文档。失败路径清理连接；已失效连接在 open/headers 阶段失败时按原有有界重试重建。
- 头解析上下文位于 worker 独占的静态会话状态，不让 callback 保存已退出函数的栈指针。
- 歌曲页读取后、分配歌曲数组/发送 UI 事件前释放 TLS。语义校验失败、取消、空曲库等路径也统一释放，不让后台闲置连接占用播放/下载 RAM。
- 首页进入在线/缓存页不再强制刷新版本：已验证的版本信息在本次开机内有效五分钟；主动“刷新”仍立即重查。未保存整个歌单页，也不写 Flash 缓存元数据。
- 播放选曲请求继续固定到所显示的 release，不在选曲时因过期自动切换 release。
- 保留证书校验、Basic auth、不可变路径、长度/JSON 校验与禁止重定向。

## 计时与验收

新增安全日志 `Catalog HTTP`（每份文档头部完成及总耗时）和 `Catalog ready`（总耗时、连接次数、歌曲总数），不打印凭据。`connections` 统计 HTTP_EVENT_ON_CONNECTED，不能在未测前宣称已经完成连接复用。

正式测试：`tests/device_catalog_latency.commands`，依赖已有设备账号、初始六首 device-v1 曲库；验证首次加载、再次进入、主动刷新均成功，并分别只有一次连接。

验证结果：42 项静态测试通过，在线测试版、正常在线版和离线版构建通过，`git diff --check` 通过。首次刷机因设备未连接失败，接回设备后完成以下回归。

## 真机结果

`build/catalog-speed-device2.log`：在网络已就绪后进入列表（不含开机配网/校时等待）。

| 操作 | worker 总耗时 | TLS 连接数 |
| --- | ---: | ---: |
| 首次进入（current + manifest + page） | 4793 ms | 1 |
| 五分钟内再次进入（page） | 4161 ms | 1 |
| 主动刷新（三份文档） | 4758 ms | 1 |

首次 current 请求 4169 ms，复用连接后的 manifest 305 ms、page 312 ms。由此确认减少了重复握手开销；单连接首请求约四秒仍包含 DNS/TCP/TLS/HTTP，不将其全部归因于密码学计算。以上是一轮实测，不是网络条件无关的时延保证。

`build/catalog-speed-stream.log`：完整收取 857146 B，第一首解码至 `Playback completed: song=16`；自动下一首、暂停/恢复、唤醒和停止返回均通过。最低内部空闲内存 11348 B，未记录 TLS 分配/读取错误或堆检查失败；五首缓存保留。没有重新执行破坏性缓存迁移脚本。

已 app-flash 回 `build/tls-release` 正常固件（关闭测试控制台）；启动确认五首本地歌曲、用户现有音量 7/10、随机模式保留，联网校时成功。未更改歌曲、账号、服务器或分区。

弱网重连、取消及账号/源站变更仍需额外覆盖；本轮软件日志验证不代替听音与长期压力测试。
