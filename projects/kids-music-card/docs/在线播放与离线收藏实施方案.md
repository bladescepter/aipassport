# 在线播放与设备端离线收藏实施方案

> 状态：历史设计方案，设备端 v1 的四项首页、手动缓存/配网与切歌代码已实现并构建，完成一轮有限真机回归；实际在线/下载验收仍待服务器。当前状态见 [设备端 v1 交付与验证](设备端-v1-交付与验证.md)，实际服务器协议见 [曲库 API v1](曲库API-v1.md)，源站暂定 `https://kidmusic.xiyuan.wiki`。本文的分类歌单等未实现建议不属于 v1 完成功能。
> VPS 实测与部署计划见 [VPS 静态曲库部署规划](VPS-静态曲库部署规划.md)。细化建议与迁移决策均单独标注，不视为已经确认或实现。
> 当前实现以 [README.zh_CN.md](../README.zh_CN.md) 为准；不改写历史需求草案。
> 本文所有未特别标注的接口、模块名、目录和参数均为拟议设计；开发时通过测试确定最终值。

## 1. 目标与范围

在不更换 FoloToy AI Passport 硬件的前提下：

1. 通过 2.4 GHz Wi-Fi 访问 VPS，流式播放远程歌曲，不先下载整首歌曲。
2. 在设备上浏览全部远程歌曲和分类歌单，新增歌曲无需重新刷机。
3. 在“缓存歌曲”勾选远程歌曲，最多选择 5 首；完整下载后可断网播放，并能确认移除本机副本。
4. 使用三键；音量移到系统设置（1–10），播放页短按上下改为上一首/下一首，保留确定键暂停/恢复与息屏行为。
5. 手机或电脑只负责配网、上传和整理曲库，不是选择离线歌曲的必要入口。

首版不做：外接 SD 卡、硬件更换、自动缓存最近播放、整张歌单批量下载、OTA、歌词、封面、公开歌曲搜索、云端同步设备收藏。

## 2. 现状与约束

### 2.1 设备与代码

- ESP32-C3，8 MB Flash，无 PSRAM；ESP-IDF 5.5.3。
- ES8311 / I2S 音频输出；现有固定点 Opus 解码器继续使用。
- 音频格式：16 kHz、单声道、32 kbps CBR、20 ms 帧。
- 文件封装：重复的 `2 字节小端长度 + Opus 帧`，不是标准 Ogg Opus；不改为 MP3。
- P0 已把 `main/music_app.c` 接入统一音频源和帧读取接口；本地播放依赖音乐分区挂载，在线源不依赖挂载成功。默认离线/P0 双配置已构建，真机已确认 P0 启动，尚未验证在线播放。
- `main/music_catalog.h` 是编译期目录，随机播放也使用按歌曲总数分配的数组；需要改为运行时目录。
- 默认配置用 `CONFIG_APP_NO_BLOBS=y` 排除无线二进制库；SDK 5.5.3 的隐藏选项 `ESP_WIFI_ENABLED` 在本芯片上会自动为 `y`。P0 需允许二进制库并显式开启联网试验，最终生效值见本地构建记录。
- 当前 `factory` 为 `0x240000`（2.25 MiB），`musicfs` 为 `0x5B0000`（约 5.69 MiB）。不预先修改分区，先测联网固件体积。
- 中文字体为子集，在线新增歌名不代表设备具备对应字形。

### 2.2 VPS 只读检查结论

方案讨论时检查的现有 VPS：2 个逻辑 CPU、约 3.6 GiB 内存（当时可用约 1.9 GiB）、系统盘约 69 GB（当时可用约 35 GB）；已运行 Docker，Caddy 已承担 80/443 HTTPS 入口。宿主机 PATH 未找到 ffmpeg，不代表其他容器没有安装。

上述是当时快照，不是持续资源保证。部署前重新检查磁盘、内存、Caddy 挂载及网络。云套餐流量、带宽和设备到 VPS 的实际网络质量尚未验证。

结论：复用现有 Caddy 提供静态曲库，不增加大型音乐服务器、数据库或消息中间件。原始音频优先在电脑编码后上传，避免争抢现有 VPS 服务的 CPU。

## 3. 架构

```text
家长提供音源 → 编码/发布工具 → VPS 版本化目录 + 裸 Opus 文件
                                       │ HTTPS，只读鉴权
                                       ▼
设备：Wi-Fi 管理 → 分页曲库 → 歌曲操作 / 离线管理
                         │
                 统一音频源接口
              ┌──────────┴──────────┐
          本地文件源             HTTP 缓冲源
              └──────────┬──────────┘
                    现有 Opus 解码
                         ↓
                    ES8311 / I2S
```

- “本地播放”只使用完整有效的本地副本，不隐式联网补取。
- 建议首版“在线播放”明确使用 HTTP 源，与“本地播放”区分；不增加隐式本地优先优化，避免用缓存掩盖 P0 联网问题。
- 缓存选择保存在设备，不要求上传 VPS；多台设备可各自选择。
- 本地存储挂载失败不得自动格式化；远程播放不得仅因本地存储失败而被禁止。
- 开机立即允许访问离线收藏，后台联网，不以网络成功作为进入菜单的前提。

## 4. 设备交互

### 4.1 首页与子菜单（用户已明确）

首页严格为四项，不增加第五项：

```text
在线播放 → 随机播放（置顶）／远程歌曲列表／返回
本地播放 → 随机播放（置顶）／有效本地歌曲列表／返回
缓存歌曲 → 可勾选的远程歌曲列表，最多 5 首
系统设置 → 音量调节（1–10）／Wi-Fi 连接／播放模式／返回
```

- 歌单分类可作为在线播放内部的后续扩展，不新增首页项；首版先实现完整歌曲列表及跨页浏览。
- 列表上下选择，短按确定播放；缓存页短按确定勾选/取消勾选，不触发播放。
- 所有子菜单提供明确“返回”项；列表长按不再承担旧方案的“歌曲操作”入口。长短按隔离仍使用 BSP 的 1.5 秒阈值。
- 系统设置内的音量页用上下调整 1–10，确定保存并返回，异步写 NVS；不新增播放页音量快捷键。没有历史设置时默认 8。
- Wi-Fi 页建议显示连接状态、重新连接、进入手机配网和返回，不在三键设备上输入复杂密码。
- 播放模式：随机、顺序、单曲循环；保留 NVS 持久化。

### 4.2 播放页与随机入口

用户已明确的变更：短按上键为上一首，短按下键为下一首，取消这两个键的音量调节功能。该变更限定播放页；菜单页上下仍是移动选项，音量设置页上下仍是调节数值。

其余播放页行为沿用当前实现：短按确定暂停/恢复；息屏短按确定保持息屏；息屏长按确定唤醒并继续播放；亮屏长按确定停止并返回来源列表；播放 5 秒息屏。

以下为建议细化，待实现前确认：

- 两个置顶“随机播放”入口均将模式切为随机并保存，立即开始对应集合播放；与系统设置的随机模式共用状态，不增加隐藏的第二套模式。
- 点击具体歌曲从该曲开始，后续遵循设置中的模式。
- 线上与本地分别形成独立播放范围；上下切歌不跨范围，不把随机入口/返回项当作歌曲。
- 手动上一首/下一首覆盖当前单曲循环动作；切到新曲后继续单曲循环。顺序范围首尾循环。
- 随机模式下“上一首”优先回到有限历史记录，下一首沿已有前进历史或产生下一随机曲；跨轮不承诺无重复，单轮保证范围见 4.4。
- 息屏短按上下切歌但保持息屏；切歌后保留当前暂停/播放状态。长按上下不新增含义。

### 4.3 勾选缓存与容量提示

- “缓存”是用户主动保留的持久离线副本，不是自动淘汰的临时缓存。
- 跨页共享一个最多 5 首的选择集合；已缓存、排队、下载中和待确认新增项合计不能超过 5，失败项仍占选择名额直到用户取消。
- 第 6 首不允许勾选，并提示上限；不能默默替换或删除先前歌曲。
- 建议采用“勾选 → 应用更改 → 确认”流程，勾选时不立即下载或删除；确认页列明新增、移除、总容量和可用空间。
- 下载时显示进度并允许取消；状态至少区分未缓存、待下载、下载中、校验中、已缓存、失败。只有完整校验成功的文件进入本地播放集合。
- 首版只在停止播放后下载；下载与播放独占 TLS。开始播放时在安全边界暂停下载并释放网络资源，明确提示“停止播放后下载”。建议进入配网前提示暂停播放/下载，避免竞争峰值内存；不得未经提示打断播放。
- 取消已缓存歌曲的勾选只形成移除提案，必须确认后才执行；不修改 VPS 文件。空间不足时保留旧文件，不自动腾空间。
- 本地独有且来源不可恢复的文件先备份或导出；远程歌曲下架不能自动删除本地副本。
- 现有 6 首歌曲是旧版资源，迁移前保留并独立标识，不因为新上限自动删掉第 6 首；它们不提供额外缓存名额，但会占真实存储空间。建议升级时进入迁移确认页，未完成迁移前只允许旧曲播放、不新增缓存；如何整理为新的最多 5 首集合须在备份和远端音源验收后确认。

### 4.4 断网与播放模式

| 场景 | 行为 |
| --- | --- |
| 已下载歌曲 | 直接本地播放，不等待服务器 |
| 未下载歌曲，网络正常 | 缓冲后在线播放 |
| 未下载歌曲，无网络 | 提示不可用，并提供本地播放入口 |
| 在线播放中断网 | 消耗缓冲，有限重试，超时提示；不能无限卡住 |
| 网络恢复 | 后台恢复连接，不打断本地播放 |
| 离线顺序/随机播放 | 仅遍历本地有效歌曲，空集合给出提示 |

在线顺序/随机以当前歌单或全部歌曲为播放范围；离线收藏以本地集合为范围。网络播放最终失败时先提示，不悄悄换成无关歌曲；用户进入本地播放后继续播放。单曲循环的远程歌曲不可用时不无限重试。

随机播放不能为海量曲库保留完整元数据数组。可先为有上限的曲库使用紧凑索引洗牌，并公布上限；更大规模采用可复现的索引排列。必须在实现中明确一轮不重复的保证范围，不将“当前页随机”称为整个歌单随机。

## 5. 静态曲库协议（v1 草案）

### 5.1 URL 布局

```text
/v1/current.json
/v1/releases/<release_id>/manifest.json
/v1/releases/<release_id>/playlists/0000.json
/v1/releases/<release_id>/tracks/all/0000.json
/v1/releases/<release_id>/tracks/<playlist_id>/0000.json
/v1/audio/<sha256>.opus
```

`current.json` 指向不可变 release；manifest 包含 schema 版本、歌曲总数、歌单总数、分页大小、页数及音频格式。歌单列表本身也分页，避免只解决歌曲分页而遗漏歌单规模。

歌曲页示意（占位值不用于真实发布）：

```json
{
  "schema_version": 1,
  "release_id": "release-example",
  "page": 0,
  "total_pages": 1,
  "tracks": [
    {
      "id": "track-0001",
      "title": "小星星",
      "duration_ms": 180000,
      "size_bytes": 738000,
      "sha256": "<64位十六进制哈希>",
      "audio_path": "/v1/audio/<sha256>.opus"
    }
  ]
}
```

### 5.2 约束

- 歌曲 ID 稳定且不复用；替换音频保留歌曲 ID，但生成新哈希和 URL。
- 每页初始建议 20 首，上限建议 30 首、响应体上限 16 KiB；最终值经内存验证确定。
- 限制标题长度、ID 长度、计数、JSON 深度及 URL 长度；未知 schema 明确拒绝。
- 设备仅接受配置源站下的相对音频路径，拒绝路径穿越、任意外域和向外域转发凭据。
- 目录版本切换只在安全边界进行；浏览和当前播放固定一个 release，不能混用不同版本分页。
- RAM 只保存当前页和有限相邻页。断网保证离线收藏可见，不承诺完整远程目录离线可见。
- 下载歌曲的标题、ID、哈希、文件大小独立保存，不能依赖远程目录缓存才能播放。
- 新版本音频不得自动覆盖已收藏的旧版；更新视为需要空间和确认的替换操作。

### 5.3 发布流程

1. 提供有使用权的原始音频，复用 `tools/encode_music.py` 编码核心。
2. 为在线曲库增加独立发布入口，生成哈希、分页、manifest、字形检查报告；不得让整库受本机 SPIFFS 容量检查限制。
3. 本机资源打包 `tools/pack_music.py` 仍保留容量检查，用于离线镜像，不能拿它打包整个远程曲库。
4. 上传音频和新的不可变 release，检查每个引用文件存在、大小和哈希一致。
5. 验证分页和鉴权后，原子切换 `current.json`，最后才让设备发现新版本。
6. 保留上一版供回滚；旧 release/音频清理需先备份和 dry-run，不在首次部署中自动删除。

现有编码工具会生成本机目录，在线发布需审查并解耦其副作用；不能宣称现有工具已经支持上述发布协议。

## 6. 播放与网络实现

### 6.1 模块划分建议

| 模块 | 职责 |
| --- | --- |
| `music_app` | UI、按键和应用状态，仅处理事件 |
| `music_catalog` | 动态目录、分页、稳定 ID、播放范围 |
| `music_source` | 本地/HTTP 统一 open/read/cancel/close 接口 |
| `music_network` | Wi-Fi、配网、连接状态、有限重试 |
| `music_download` | 下载队列、临时文件、校验和取消 |
| `music_storage` | 本地索引、容量、恢复和移除 |

模块名为建议，不要求一次性大规模拆分。文件读取、网络等待、Flash/NVS 写入、解码、I2S 操作都不得放入 UI/LVGL 任务或按键回调。

### 6.2 流式读取

- 网络任务向有界环形缓冲写入压缩数据；播放任务从缓冲取完整帧并解码。
- 初始缓冲候选为 16–32 KiB，按可用内存实测缩减；约覆盖 4–8 秒音频。
- 32 kbps 音频约 4000 B/s，加上每秒 50 个两字节长度前缀，共约 4100 B/s。
- 起播阈值和完整缓冲容量分离；先测试约 1 秒起播阈值，再根据网络调节。
- TCP/HTTP 短读不是 EOF；帧长度字段和帧正文都必须累计读取。
- 对零长度、超限长度、半帧 EOF、解码错误显式报错，不能越界或无限等待。
- 阻塞等待须有期限，可被停止/切歌取消；沿用 generation 标记，丢弃旧请求的数据和事件。
- 无数据时等待或进入缓冲状态，不忙轮询，不向解码器提交不完整帧。

### 6.3 重连与暂停

音频 URL 不可变，HTTP 支持 Range。重连记录精确的已接收字节偏移，保留已有缓冲和半帧；验证 `206`、`Content-Range` 和文件总长。服务器忽略 Range 返回 `200` 时不得把响应拼接到旧数据后，应受控重启歌曲并提示。处理 `416` 和版本不匹配。

暂停时使用背压停止继续填充，禁止缓冲无限增长；长期暂停导致连接断开后按准确位置恢复。保持原解码状态用于同一流的短暂恢复；首版不承诺任意进度跳转或断电续播。

建议初始策略：连接/读取超时均有上限，总恢复时间约 10 秒，最多 2 次重试；由弱网测试调优。按键事件响应不应随该超时一起阻塞。

## 7. 离线存储与掉电恢复

### 7.1 容量预算

3 分钟歌曲约 738 KB（十进制）。用户选择上限固定为 5 首，但这不是任意 5 首都能放下的承诺；数量与实际字节容量必须同时通过检查。实际可保存量取决于歌曲时长、SPIFFS 开销、安全余量、临时文件和最终分区布局。

现有 6 首裸 Opus 合计 4,943,124 B，约为 5,963,776 B 分区的 82.9%，还未计算 SPIFFS 元数据。不能在不整理旧资源的前提下承诺再存入 5 首；也不能把分区大小减音频字节数作为真实文件系统可用空间。

- 按实际文件大小预检，不用歌曲数量估算容量。
- 初始可将总占用软上限设为分区约 70%，再据 SPIFFS 实测修订；预留元数据和回收空间，不填满分区。
- 更新时同时容纳旧文件和新临时文件；空间不足保留旧文件，要求用户另行整理。
- 控制打开文件数；现有挂载 `max_files` 必须结合新模块访问情况复核。

### 7.2 状态机

```text
未保存 → 排队 → 下载临时文件 → 大小/哈希校验 → 提交索引 → 已保存
                      │               │
                      └── 失败/取消 ──┘ → 不标记可用
```

- 临时文件与正式文件分开命名，校验成功才提交本地索引。
- 本地索引使用带版本和校验的双份记录或等效可恢复机制；启动时核对索引与文件。
- 不把单次 SPIFFS rename 当成整个多文件事务具备掉电原子性的保证。
- 重启后完整且验证通过的文件可恢复入库；不完整临时文件可续传或重新下载，不显示为收藏。
- 首版允许中断后重新下载；若实现续传，必须校验 Range，并对完整文件最终计算哈希。
- 确认移除前停止对该文件的使用；通过可恢复的删除状态避免索引仍指向已删除文件。
- 开机无需每次全量哈希所有收藏；保存时完整校验，启动检查记录和大小，损坏时标为不可用并支持重新下载。

## 8. 配网、安全和 VPS 部署

### 8.1 配网

首次无凭据时提示配网入口（不阻塞本地启动），或从“系统设置 → Wi-Fi 连接”选择配网，开启临时 SoftAP，通过手机配置页输入家庭 2.4 GHz Wi-Fi。配网窗口超时关闭；再次配网保留离线歌曲。凭据保存在设备 NVS，不上传 VPS、不写日志、不提交 Git。

配置页不依赖必须成功弹出的 captive portal，屏幕显示可手动打开的地址。配网期间暂停下载；正常运行关闭配网服务，降低内存占用和暴露面。

### 8.2 安全

- 使用 HTTPS 并验证服务器证书；准备合理的时间同步/证书时间校验流程，失败时仍允许本地播放，不能通过关闭验证绕过错误。
- 每台设备使用可撤销的只读凭据；Caddy 保护全部目录、分页和音频路径，不能只保护首页。
- 可使用 Caddy 支持的 Basic Auth over HTTPS，服务端保存密码哈希；设备固件中不提交真实凭据。
- 不使用 URL 查询参数携带令牌；拒绝不安全的重定向，不记录授权头。
- 无浏览器后台时不新增管理 API；设备无上传、删除 VPS 文件或服务器管理权限。
- 无安全启动/Flash 加密时不能承诺抵御物理提取凭据；首版通过最小权限和撤销控制风险。

### 8.3 部署步骤（须在实施时审核配置后执行）

1. 确认拟用独立子域名、DNS、证书、云端带宽和流量额度；本文不假定域名已经配置。
2. 备份现有 Caddy 配置和容器部署定义，记录恢复方式。
3. 创建专用数据目录（建议 `/opt/data/kids-music/`），不混入现有其他服务的数据。
4. 将曲库只读挂载到 Caddy；容器挂载变更通常需要按正式部署定义重建容器，不能认为 reload 会新增挂载。评估对现有站点的影响。
5. 添加独立站点及只读鉴权，验证配置后受控部署；不新增 80/443 之外的公网入口。
6. 验证未授权拒绝、授权成功、证书链、正确 MIME/字节内容、Range 和 Content-Length；避免内容转换破坏字节偏移。
7. 验证现有站点仍可用，使用真实设备网络播放测试歌曲。
8. 失败时恢复原配置/部署定义；保留新增曲库文件，不破坏其他服务。

没有网页后台的首版，上传使用既有 SSH/SFTP 等受控渠道，不开放匿名上传。音频与原始文件不进入 Git。

## 9. 字体与资源发布

- 扩充常用中文覆盖并测量固件体积；保留字体许可证。
- 发布工具检查全部 UI 文案和歌曲显示名的字形覆盖。
- 缺字时阻止无提示发布，提供报告；可使用已覆盖字形组成的简短显示名，保留原始元数据。
- 首版不实现网络动态字体；“新增歌曲无需刷机”以显示名处于支持字符范围为前提。

## 12. 完成定义

- 设备能浏览完整远程曲库和歌单，而不是固件内置的固定列表。
- 用户可直接在设备上选择离线保存、查看进度和移除副本。
- 没有网络仍可开机、浏览及播放有效收藏。
- 首页严格为在线播放、本地播放、缓存歌曲、系统设置；前两个列表置顶随机入口。
- 缓存选择最多 5 首，同时满足字节容量约束；没有未经确认的自动删除。
- 音量只在系统设置调节为 1–10；播放页短按上下为上一首/下一首，确定键和息屏行为按新版约定执行，没有网络请求阻塞 UI。
- VPS 曲库可发布、验证、回滚；凭据和音频不进入仓库。
- 编译、静态测试、服务器验证、真机验收分别记录，明确尚未完成的项。
